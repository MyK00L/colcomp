\section{Introduction}
Given a graph, where to each node is associated a color,
a colorful component of that graph is a connected subgraph such that no two nodes have the same color.

The "Minimum Orthogonal Partition" (MOP) problem consists in deleting the minimum number of edges from a graph
so that the remaining graph consists only of colorful components.

In \parencite{ccc2025} is given an introduction to MOP, "Maximum Edges in transitive Closure" (MEC) and "Minimum Colorful Components" (MCC) problems,
with their applications (mainly in biology and networks) and solutions based on branch and cut.

In particular, MOP was introduced in \parencite{he2000}, where an approximation algorithm was given, and an exact approach was first given in \parencite{mop2012},
where it is also shown to be NP-hard even for graphs with $3$ colors and a maximum degree of $6$, or for trees with diameter $4$.

\section{Mathematical formulation}
\subsection{Definitions}
In the MOP problem there is a graph
$G = (V,E,C)$ where $V$ is the set of nodes, $E$ is the set of edges, and $C$ is the set of colors.

$c : V \to C$ is a function giving the color of each node: for a node $u \in V$ its color is $c(u)$.

The problem consists in removing the minimum number of edges $E' \subset E$ such that in the resulting graph $G' = (V, E', C)$,
all connected components are colorful.

It is equivalent to find a way to partition the graph into $Q$ colorful subgraphs,
such that the sum of edges within them is maximized.
Note that with this formulation the subgraphs do not necessarly need to be connected.

\subsection{Integer Linear Programming formulation}
Given the last definition, MOP can be formulated as follows:

\begin{numcases}{\label{ilp}}
	\max \sum_{q \in Q}{\sum_{(u,v) \in E}{e_{q,(u,v)}}} \quad \text{s.t.} \nonumber \\
	x \in \{0,1\} ^{ Q \times V } \nonumber \\
	e \in [0,1]^{ Q \times E } \nonumber \\
	\forall u \in V \quad \sum_{q=1}^{Q}{x_{q,u}}\le 1 \label{ilp1} \\
	\forall q \in Q \forall k \in C \quad \sum_{u \in V : c(u) = k}{ x_{q,u} } \le 1 \label{ilp2} \\
	\forall q \in Q \forall (u,v) \in E \quad e_{q,(u,v)} \le x_{q,u} \land e_{q,(u,v)} \le x_{q,v} \label{ilp3}
\end{numcases}

Where $x_{q,u}$ is $1$ if node $u$ is present in subgraph $q$.\\
For the edge $(u,v)$, $e_{q,(u,v)}$ is $\min(x_{q,u},x_{q,v})$, which is $1$ if edge $(u,v)$ is present in subgraph $q$.\\
(\ref{ilp1}) Are the partition constraints.\\
(\ref{ilp2}) Are the color constraints.\\
(\ref{ilp3}) Are to make $e_{q,(u,v)} \le \min(x_{q,u},x_{q,v})$ for the objective.

And $Q$ is a bound on the number of subgraphs in an optimal solution, since the exact number is hard to know.

The bounds for the edges (\ref{ilp3}) can be made tighter, as will be seen in (\ref{pricing_cr_edge_const}).

\subsection{Bound on Q}
A simple upper bound to $Q$ would be $|V|$, in \parencite{ccc2025} better bounds are shown for when the subgraphs need to be connected.

If, like in the above formulation, the subgraphs don't need to be connected, we can do better:\\
Define $nc : C \to N$ such that $nc(k) = | u \in V : c(u) = k |$.\\
Call a partitioning \textit{minimal} if all pairs of subgraphs have at least one color in common.\\
There is always an optimal solution that is minimal: if it is not, you can keep merging subgraphs that have no color in common, until it is minimal.\\
Consider the graph of a partition, where each node is a subgraph and there is an edge between two subgraphs if they have at least one color in common.\\
In a minimal solution, such graph is a clique, so it has $q = \frac{s \cdot (s-1)}{2}$ edges if $s$ is the number of subgraphs, and $s = \sqrt{2q + \frac{1}{4}} + \frac{1}{2}$ .\\
Each color $k$ in the original graph can make at most $\frac{nc(k) \cdot (nc(k)-1)}{2}$ edges.\\
So there are at most $K = \sum_{k \in C}{\frac{nc(k) \cdot (nc(k)-1)}{2}}$ edges.\\
Thus a minimal solution always has at most $Q = \lfloor \sqrt{2K + \frac{1}{4}} + \frac{1}{2} \rfloor$ subgraphs.

\section{Branch and price algorithm}
\subsection{Master and Pricing problems}
In the ILP formulation, (\ref{ilp1}) are linking constraints, we can separate these from the others obtaining a Dantzig-Wolfe decomposition \parencite{dwd} with identical subproblems.

We convexify constraints (\ref{ilp2}) and (\ref{ilp3}), and do column generation, where constraints in (\ref{ilp1}) remain in the master problem and the others go in the pricing subproblem.

The restricted linear master problem is:
\begin{numcases}{}
	\max \sum_{i=1}^{p} \sum_{q=1}^{Q} \sum_{(u,v) \in E} e^{(i)}_{q, (u,v)} \cdot \theta_i \quad \text{s.t.} \nonumber\\
	\theta \in [0,1]^{p} \nonumber\\
	\sum_{i=1}^{p} \theta_i = 1 \label{rlmp_1_conv}\\
	\forall u \in V \quad \sum_{i=1}^{p} \sum_{q=1}^{Q} x_{q,u}^{(i)} \cdot \theta_i \le 1 \label{rlmp_1_part}
\end{numcases}
Where $p$ is the number of generated columns.

And the pricing subproblem is:
\[
\begin{cases}
	\max -\mu + \sum_{q=1}^{Q} (\sum_{(u,v) \in E}{e_{q,(u,v)}} - \sum_{u \in V}{\lambda_u x_{q,u}}) \quad \text{s.t.}\\
	x \in \{0,1\} ^{ Q \times V }\\
	e \in [0,1]^{ Q \times E }\\
	\forall q \in Q \forall k \in C \quad \sum_{u \in V : c(u) = k} x_{q,u} \le 1\\
	\forall q \in Q \forall (u,v) \in E \quad e_{q,(u,v)} \le x_{q,u} \land e_{q,(u,v)} \le x_v\\
\end{cases}
\]
Where $\mu$ is the dual variable of the convexity constraint (\ref{rlmp_1_conv}), and $\lambda$ is the dual variable of the partition constraints (\ref{rlmp_1_part}).

Of course, since the subproblems are independent (and identical), they can be separated,
so the $Q$ dimension is now superfluous and the problem can be rewritten as:
\[
\begin{cases}
	\max -\mu + Q(\sum_{(u,v) \in E}{e_{(u,v)}} - \sum_{u \in V}{\lambda_u x_u}) \quad \text{s.t.}\\
	x \in \{0,1\} ^{V}\\
	e \in [0,1]^{E}\\
	\forall k \in C \quad \sum_{u \in V : c(u) = k} x_{u} \le 1\\
	\forall (u,v) \in E \quad e_{(u,v)} \le x_{u} \land e_{(u,v)} \le x_v\\
\end{cases}
\]

We can to get rid of $Q$ in the master problem by having $\theta$ sum up to the number of subgraphs instead of $1$:
\[
\begin{cases}
	\max \sum_{i=1}^{p} \sum_{(u,v) \in E} e^{(i)}_{(u,v)} \cdot \theta_i \quad \text{s.t.}\\
	\theta \in [0,1]^{p}\\
	\forall u \in V \sum_{i=1}^{p} \theta_i \cdot x_u^{(i)} \le 1\\
\end{cases}
\]

And the pricing subproblem's objective will change to:
$\max \sum_{(u,v) \in E}{e_{(u,v)}} - \sum_{u \in V}{\lambda_u x_u}$

Any solution to the pricing subproblem also solves the Lagrangean relaxation associated to the initial ILP formulation when Lagrangeanizing (\ref{ilp1}):
\begin{numcases}{}
	\max \sum_{u \in V}{\lambda_u} + Q(\sum_{(u,v) \in E}{e_{(u,v)}} - \sum_{u \in V}{\lambda_u x_u}) \quad \text{s.t.} \label{lr_obj}\\
	x \in \{0,1\} ^{V} \nonumber \\
	e \in [0,1]^{E} \nonumber \\
	\forall k \in C \quad \sum_{u \in V : c(u) = k} x_{u} \le 1 \nonumber \\
	\forall (u,v) \in E \quad e_{(u,v)} \le x_{u} \land e_{(u,v)} \le x_v \nonumber
\end{numcases}
So, whenever we solve a pricing subproblem optimally, with $\lambda = \bar{\lambda}$,
obtaining the solution $x^*, e^*$,
we also obtain a dual bound for free by applying $\bar{\lambda}, x^*, e^*$ to (\ref{lr_obj}).

\subsection{Braching strategy}
I branch on edges, like is done in \parencite{mop2012}.
On one side of the branch, the chosen edge will be deleted, on the other side its nodes will be merged.
This means that in the pricing problem, the edges will now be weighted, and each node can have multiple colors associated to it.

Branching is done on the edge $(u,v)$ whose $\sum_{i=1}^{p} e^{(i)}_{(u,v)} \cdot \theta_i$ is closest to $0.5$ in the RLMP solution.

Exploration is done best first:
at each step I explore the node with the best dual value as computed by its parent node,
exploring the shallowest one when multiple nodes have the same dual value.

Once in a while, so as to match the time spent lowering the dual bound, after solving the LMP,
I solve the Restricted Master Problem (which is a weighted set packing problem) with ILP on all columns generated so far,
which usually gives good primal bounds, often good enough to close the BnP on the first node.
I don't do it at each step, since, at each BnP node other than the root, only a few columns are generated, and searching for the primal bound would take up most of the time.

I always keep all generated columns, and feed all compatible ones into each instance of the master problem.

\subsection{Hot-start}
\label{hotstart}
Columns were hot-started with heuristic solutions.

In \parencite{mop2012} a \textit{Merge heuristic} was proposed,
They define a cut cost and merge cost, and at each step contract the edge maximizing cut cost minus merge cost.

I use a modified heuristic:\\
First edges are ordered by decreasing cut cost minus merge cost.\\
Then we contract each edge in that order, ignoring those that would merge two nodes having the same color.\\
Then we modify the ordering by swapping a contracted edge with an edge that appears later in the ordering,\\
If the new ordering produces a worse score, we undo the swapping.\\
Then repeat trying to swap other edges, for some number of iterations.\\
I call it \textit{Karger heuristic} in the code because it was inspired by Karger's randomized algorithm for minimum cut \parencite{karger}.

I default to 2000 iterations, and it usually achieves better results.
It can be slower on smaller graphs, but it's faster on larger graphs as you don't have to compute the merge costs at each step.

I also add columns generated by a greedy approach that starts at each node,
and keeps adding nodes, without taking two nodes with the same color, trying to minimize the cut to the rest of the graph at each step.

One other interesting thing one can do is a large scale neighbourhood search based on cyclic exchanges:
for each color you can create a directed graph where each node represents a component,
and an edge represents moving the node of that color from one component to another,
with its weight being the number of edges (in the original graph) between that node and the new component minus those within the current component.
Also add an empty component to represent just removing the node from its component.
A positive weight simple cycle in this graph (which can be found in $O(nm)$),
represents a list of node transfers between components that improves the solution.\\
On smaller graphs that are tractable with an exact solution, this does not often improve on the previous heuristics.
However, on larger graphs, this search applied to the result of one of the previous heuritics can improve the solution by a lot.

\subsection{Stabilization}
This column generation approach, even without employing any stabilization technique,
did not seem to run into major stability issues.
Still, I used single parameter stabilization, first described in \parencite{sps}.

On average solutions tend to converge faster, but some columns need to be discarded.

\subsection{Preprocessing}
In \parencite{mop2012}, 3 rules for preprocessing are proposed.

Note that, as opposed to \parencite{mop2012}, I maximize for edges that are not deleted,
and think of an edge as in the solution when it was not deleted.

Rule 1:
If a connected component is colorful, remove it from $G$ and add its edges to the solution.

Rule 2:
Let $B \subseteq E$ be a minimal edge cut of size $t$, partitioning $G$ in $G_B$ and $G \setminus G_B$.
Let $N$ be the nodes incident in $B$ that are not in $G_B$.
If $G_B$ is colorful, t-edge connected, and all colors in $N$ also appear in $G_B$, remove $B$.

Rule 3:
Same as Rule 2, but $N$ has some colors not in $G_B$, then merge the nodes in $G_B$.
If merging nodes is not an option, you can still delete all edges in $B$ where the node in $N$ has a color present in $G_B$.

I propose a rule weaker than Rule 2 that also finds the edges deleted by Rule 3:\\
Let $G_B$ be a colorful subgraph, $B$ the minimal edge cut that separates it from $G \setminus G_B$.
For any $(u,v) \in B$ where $u \in G_B$ and $v \in G \setminus G_B$,
such that $\exists u' \in G_B : c(u') = c(v)$,
if $|mincut_{G_B}(u,u')| \ge |B|$, remove $(u,v)$.\\
Where $|mincut_{G_B}(u,u')|$ is the size of a minimum cut between $u$ and $u'$ within $G_B$.

The proof is the same as that given for Rule 2 in \parencite{mop2012}:\\
If a solution $S \subseteq E$ contains $(u,v)$, within $G_B$,
at least $|mincut_{G_B}(u,u')| \ge |B|$ edges must have been deleted, call them $X$.
Then $S' = (S \setminus B) \cup X$ is also a solution, and $|S'| \ge |S|$.

This rule is weaker as it only asks for the cut between two nodes to be $\ge |B|$, and it can delete a single edge at the time.
So among the edges in $B$, where the color of $v$ is present in $G_B$ too, the edge associated to the $i_{th}$ biggest cut (among those mentioned by the rule), of size $t_i$, can be removed if $t_i - (i-1) \ge |B|$.

For the original Rule 2, you could check for t-edge connectivity in $O(nm) = O(|C|^3)$ with the algorithm described in \parencite{matula}.\\
To check for this rule for a component can be less efficient:
you have to check for $O(|C|)$ cuts between pairs of nodes (if $|B| \ge |G_B|$, all cuts are $<|B|$ and since $G_B$ is colorful, $|G_B| \le |C|$),
and if you check each of them with a simple $O(nm)$ max-flow algorithm, the complexity would be $O(|C|^4)$.
In theory there exist faster algorithm for max-flow or all-pairs minimum cut, but I found $O(|C|^4)$ to be sufficient.

To apply this rule, I first get a partition with one of the heuristics mentioned in \nameref{hotstart},
then I iteratively remove all edges that can be removed.
Starting from a partition has the advantage that if you remove an edge with a bound for some component,
$|B|$ decreases also for the other component incident to that edge,
and you can check its edges again without having to recompute cuts.

I also try single components generated from a greedy that starts at each node,
and adds nodes trying to keep the cut to the rest of the graph as small as possible.

\section{Pricing subproblem}
The pricing subproblem consists in finding the colorful subgraph maximizing edge weight sum minus node costs.
Where each node has multiple colors and a real cost, and each edge has an integer weight.

Define $w(u,v)$ to be equal to the weight assoctiated to edge $(u,v)$, or $0$ if there is no such edge.

For each node $u$, call $\lambda_u \ge 0$ its cost.

Since each node can have multiple colors, $c(u) \in 2^C$,
but in many cases I relax the problem, thinking of nodes as having a single color.
In those cases I will use the shorthand $c(u)=k$ to mean $min_{c' \in c(u)}{c'} = k$.\\
Since most of the pricing steps happen in the root of the BnP,
where each node only has one color, this relaxation is not felt too much.

\subsection{Preprocessing}
For simplicity, consider each node to have a single color during the preprocessing.

A node $u$ is useless if $-\lambda_u + \sum_{k \in C} \max_{v : c(v)=k} w(u,v) < 0$

An edge $(u,v)$ is useless if $-\lambda_u -\lambda_v + \sum_{k \in C \setminus \{c(u),c(v)\}} \max_{u' \in V : c(u')=k} w(u,u')+w(v,u') < 0$

We can iteratively delete useless nodes and edges to obtain a smaller problem.

\subsection{ILP formulation}
\begin{numcases}{\label{pricing_ilp}}
	\max \sum_{(u,v) \in E}{e_{(u,v)} \cdot w(u,v)} - \sum_{u \in V} \lambda_u \quad \text{s.t.} \nonumber \\
	x \in \{0,1\}^{V} \nonumber \\
	e \in [0,1]^{E} \nonumber \\
	\forall k \in C \quad \sum_{u \in V : k \in c(u)} x_{u} \le 1 \label{pricing_ilp_color} \\
	\forall (u,v) \in E \quad e_{(u,v)} \le x_u \land e_{(u,v)} \le x_v \label{pricing_ilp_edge}
\end{numcases}
Where (\ref{pricing_ilp_color}) are the color constraints,
and (\ref{pricing_ilp_edge}) are the edge constraints that,
as mentioned earlier, can be made tighter (as will be seen in (\ref{pricing_cr_edge_const})).

\subsection{Branch and Bound solution}
I only consider connected components in this solution, which has the advantage that it restricts the search, especially for sparse graphs,
and the disandavtage that we can no longer use the tighter bound we obtained on $Q$, when computing the Lagrangean dual.

I branch on the nodes, setting $x_u$ to $1$ or $0$, and call the set of taken ($x_u=1$) nodes $U$.
At the root node, I do n-ary branching: for each branch I forbid all nodes taken in previous branches, and take a node.
At other nodes I do binary branching, taking or forbidding the most promising node by some heuristic.
I return multiple columns, each found in the subtree of a different successor of the root node,
filtering by those with reduced cost at least $\frac{1}{2}$ of that of the best one found.
Generating multiple columns at once, instead of just the best one, turned out to be a great improvement.

To bound the search, I relax the problem as follows:

If $C'$ the set of colors that do not appear in $U$,
any node further than $|C'|$ from $U$ can be discarded,
as to reach it you would have to take the same color twice at least once.

Any node $u$ with $-\lambda_u + \sum_{v \in U}{w(u,v)} + \sum_{k \in C'}{\max_{v : c(v)=k} w(u,v)} < 0$ can be discarded.

Call $\sigma(u) = -\lambda_u + \sum_{v \in U}{w(u,v)}$,\\
$V'$ the set of nodes that has not been discarded,\\
$E'$ the set of edges that has not been discarded, and\\
$C'$ the set of colors associated to nodes in $V'$ (each node having a single color).

Next I present two ways to get a useful relaxation out of this formulation.
In both, I relax by considering all subgraphs of $V'$ instead of only connected ones.

\subsubsection{Bound with continuous relaxation}
\begin{numcases}{\label{pricing_cr}}
	\max \sum_{(u,v) \in E'}{e_{(u,v)} \cdot w(u,v)} + \sum_{u \in V'} \sigma_u \quad \text{s.t.} \nonumber \\
	x \in [0,1]^{V'} \label{pricing_cr_x} \\
	e \in [0,1]^{E'} \label{pricing_cr_e} \\
	\forall k \in C' \quad \sum_{u \in V' : k \in c(u)}{x_u} \le 1 \label{pricing_cr_color_const} \\
	\forall k \in C' \forall u \in V' \quad \sum_{v \in V' : (u,v) \in E', k \in c(v)}{e_{(u,v)}} \le x_u \label{pricing_cr_edge_const}
\end{numcases}
This is a continuous relaxation of the exact solution (\ref{pricing_ilp}),\\
except that (\ref{pricing_cr_edge_const}) is a tighter bound on edges.

\subsubsection{Bound with surrogate relaxation}
I consider each node to have a single color associated to it.

I split each edge's weight across its two nodes, obtaining a surrogate relaxation for each edge of constraints (\ref{pricing_ilp_edge}) of the ILP formulation.\\

Each edge $(u,v)$ is split with $0 \le \alpha_{(u,v)} \le 1$ of its value goint towards $u$ and $1 - \alpha_{(u,v)}$ going towards $v$.

The relaxed problem looks as follows:
\begin{numcases}{}
	\max \sum_{(u,v) \in E'}{e_{(u,v)} \cdot w(u,v)} + \sum_{u \in V'} \sigma_u \quad \text{s.t.} \nonumber \\
	x \in \{0,1\}^{V'} \nonumber \\
	e \in [0,1]^{E'} \nonumber \\
	\forall (u,v), (u,v') \in E' : v' \neq v, c(v) = c(v') \quad e_{(u,v)} \cdot e_{(u,v')} = 0 \label{pricing_sr_1} \\
	\forall k \in C \quad \sum_{u \in V : k \in c(u)} x_{u} \le 1 \nonumber \\
	\forall (u,v) \in E' \quad e_{(u,v)} \le \alpha_{(u,v)} \cdot x_u + (1 - \alpha_{(u,v)}) x_v \label{pricing_sr_2}
\end{numcases}
Where (\ref{pricing_sr_2}) are the convex combinations of (\ref{pricing_ilp_edge}) from the ILP formulation,
and the extra constraint (\ref{pricing_sr_1}) makes sure that two edges incident to the same node,
associated to two nodes of the same color and cannot both contribute to the objective.

Solving it given $\alpha$ is straightforward: for each color choose the best node.
If we call $w^{(u)}(u,v) = \alpha_{(u,v)} \cdot w(u,v)$ and $w^{(v)}(u,v) = (1-\alpha_{(u,v)}) \cdot w(u,v)$,
the solution is:
\begin{equation}
\label{eqn:sr_sol}
\sum_{k \in C'} \max_{u \in V' : c(u) = k}{(\sigma_u + \sum_{k' \in C'}{ \max_{v \in V' : c(v) = k'}{w^{(u)}(u,v)}})}
\end{equation}

The best values for $\alpha$ can be found with the following linear program.
\begin{numcases}{}
	\min \sum_{k \in C} \gamma_k \nonumber \\
	\alpha \in [0,1]^{E'} \label{pricing_sr_alpha} \\
	\beta \in \mathbb{R}_+^{V' \times C'} \label{pricing_sr_beta} \\
	\gamma \in \mathbb{R}_+^{C'} \label{pricing_sr_gamma} \\
	\forall (u,v) \in E' \quad \beta_{u,c(v)} \ge w(u,v) \cdot \alpha_{(u,v)} \land \beta_{v,c(u)} \ge w(u,v) \cdot (1-\alpha_{(u,v)}) \label{pricing_sr_beta_const} \\
	\forall u \in V' \quad \gamma_{c(u)} \ge \sigma_u + \sum_{k \in C'} \beta_{u,k} \label{pricing_sr_gamma_const} \\
\end{numcases}
$\beta$ takes care of the inner $\max$ in (\ref{eqn:sr_sol}), and $\gamma$ of the outer one.

When each node has a single color associated to it,
this bound is just as tight as the one from the continuous relaxation (\ref{pricing_cr}).

In fact that these LPs are duals of each other:\\
$\gamma$ (\ref{pricing_sr_gamma}) corresponds to the color constraints (\ref{pricing_cr_color_const}),\\
$\beta$ (\ref{pricing_sr_beta}) corresponds to the edge constraints (\ref{pricing_cr_edge_const}),\\
the constraints on $\beta$ (\ref{pricing_sr_beta_const}) correspond to $e$ (\ref{pricing_cr_e}),\\
the constraints on $\gamma$ (\ref{pricing_sr_gamma_const}) correspond to $x$ (\ref{pricing_cr_x}),\\
$\alpha$ does not correspond to anything, and it can be shown to be reduntant:
to have this LP correspond 1 to 1 to the LP from the continuous relaxation,
you would have to remove $\alpha$ and rewrite (\ref{pricing_sr_beta_const}) as $\forall (u,v) \in E' \quad \beta_{u,c(v)} + \beta_{v,c(u)} \ge w(u,v)$.
The upper bound for $e$ is also superflous.

That said, solving a linear program at each node in the BnB was slow,
so I opted to just use the following heuristic for the surrogate coefficients:
$\alpha_{(u,v)} = \frac{1 - \sigma_u + \max(\sigma_u,\sigma_v)}{2 - \sigma_u - \sigma_v + 2 \cdot \max(\sigma_u,\sigma_v)}$.

I also tried to compute the optimal surrogate coefficients at the root of the BnB,
and use them for the other nodes too, but it did not perform as well.

\subsection{Heuristic pricing}
I considered several heuristic approaches to pricing.

In the end I opted for a beam-search based approach,
where each entry is a connected subgraph and I incrementally add the next node that increases the score the most.

When using heuristic pricing to generate columns, the Lagrangean dual value cannot be updated,
and the columns are not as good as with the exact approach.


\section{Experiments}
All runs were executed on a "11th Gen Intel(R) Core(TM) i5-1135G7 @ 2.40GHz" CPU, with a time limit of 180s per graph.

I generated random graphs starting from the following parameters:
$n$ is the number of nodes in the graph,
$c$ is the number of colors: each node has a uniform probability chance to be of any color,
$d$ is the amount of edges between nodes of different colors, over the total possible amount (I generate no edges between nodes with the same color).

I generated 20 graphs with parameters $n=100$, $c=6$, $d=0.1$,
and used them to test the proposed solution.

\subsection{Other random graphs}
\label{org}

In \parencite{mop2013}, random graphs were generated starting from observations on Wikipedia interlanguage link graphs.
There are five parameters:
$c$ is the number of colors,
$n$ is the number of vertices,
$p_v$ is the probability that a component contains a vertex of a certain color,
$p_e$ is the probability that there is an edge between two vertices in the same component,
$p_x$ is the probability that there is an edge between two vertices in a different component.

I used the same generator, and the same base parameters of $c=6$, $n=70$, $p_v=0.6$, $p_e=0.7$, $p_x=0.03$,
except in the plots for $p_v$ and $p_e$, where $n=120$ was used.

Two of the instances in the plot for $p_x$ ran out of time, and their data points are not shown.

\section{Conclusions}
I presented an approach based on column generation for the MOP problem.

It should be possible to adapt this approach to the MEC and MCC problems too,
where there will be a different objective for the pricing subproblem.

On graphs with higher density (like in those with high $p_x$ in section \ref{org}),
the dual bounds achieved by column generation are not very tight,
and the BnP often needs to branch a lot.
These cases could benefit by adding cuts to the algorithm (e.g. odd cycle inequalities or clique inequalities for the SPP).
Also, the choice of edge to branch on has not been explored in depth and definitely leaves room for improvement.

On graphs with higher number of colors,
the BnB solution to the pricing problem appears to be the main bottleneck,
better heuristic pricing solutions,
better heuristics for the surrogate coefficients,
or different solutions altogether, could improve the algorithm.

Faster ways to obtain good primal values,
for example heuristic solutions to the set packing,
could also help improve the overall speed.

The code is available at \url{https://github.com/MyK00L/colcomp}, and can be compiled with \texttt{make}, HiGHS needs to be installed.
